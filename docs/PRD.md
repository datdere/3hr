# 나만의 3시간 — PRD

1주일에 나만의 시간을 (기본) 3시간 가졌는지 휴대폰에서 빠르게 기록하고 확인하는 개인용 앱.

## 원칙
- **나 혼자 쓰는 도구.** 계정·서버 없음. 기록은 내 휴대폰 안에만 있다.
- **기록은 한 번의 터치.** 나만의 시간에 폰을 보지 않도록, 끝난 뒤 빠르게 남긴다.
- **지난 결과는 정직하게.** 지난 주 기록과 달성 판정은 바뀌지 않는다.

## 확정된 설계 결정

### 기반
| 항목 | 결정 |
|---|---|
| 사용자 | 나 혼자만 |
| 형태 | 휴대폰 홈 화면 앱 (PWA, 오프라인 동작) |
| 배포 | GitHub Pages (무료 계정이면 저장소 공개 필요 — 코드만 공개, 기록은 올라가지 않음) |
| 저장 | 브라우저 localStorage, 서버 없음 |

### 목표와 주
| 항목 | 결정 |
|---|---|
| 달성 기준 | 월–일 한 주 누적 시간 ≥ 목표 |
| 목표 시간 | 기본 3시간, 설정에서 변경 가능 |
| 목표 변경 시 판정 | 주마다 당시 목표를 저장해 그 주의 목표로 판정 |
| 주 시작일 | 월요일 (고정) |
| 앱 이름 | "나만의 3시간" 유지 (목표를 바꿔도 이름은 그대로) |

### 기록
| 항목 | 결정 |
|---|---|
| 기록 방식 | 끝난 뒤 빠른 입력 (타이머 없음) |
| 입력 버튼 | 30분 · 1시간 · 1시간 30분 · 2시간 + 직접 입력 |
| 함께 남기는 것 | 카테고리 태그 (선택 사항, 없으면 "미분류") |
| 태그 관리 | 기본 태그(독서·운동·취미·휴식)로 시작, 설정에서 추가·삭제·이름 변경 |
| 수정 범위 | 이번 주는 날짜 선택 추가·수정·삭제 자유, 지난 주는 잠금 |

### 돌아보기·알림·백업
| 항목 | 결정 |
|---|---|
| 통계 | 지난 주들 달성 여부와 연속 달성 주 수 + 이번 주·최근 4주 태그별 시간 비율 |
| 알림 | 앱 안 표시만: 남은 시간과 남은 날 기준 하루 페이스 |
| 백업 | 설정에서 파일(JSON) 내보내기·가져오기 |

## 화면 구성
1. **홈**
   - 이번 주 진행률 막대, 누적/목표, 남은 시간과 "남은 N일 동안 하루 X분" 페이스
   - 빠른 입력: 시간 버튼 4개 + 직접 입력 → 태그 선택(건너뛰기 가능) → 저장
   - 이번 주 기록 목록 (탭해서 수정·삭제, 날짜 변경은 이번 주 안에서만)
2. **돌아보기**
   - 연속 달성 주 수, 지난 주들 목록(✓/시간/그 주 목표)
   - 이번 주·최근 4주 태그 비율
3. **설정**
   - 주간 목표 시간
   - 태그 편집
   - 기록 내보내기·가져오기

## 데이터 모델
```
entries:  [{ id, date: 'YYYY-MM-DD', minutes, tagId | null }]
tags:     [{ id, name, archived }]        // 삭제된 태그는 과거 기록 표시를 위해 보관 처리
goals:    { currentMinutes, byWeek: { 'YYYY-MM-DD(월요일)': minutes } }
```
- 어떤 주에 첫 기록이 생기거나 그 주가 처음 표시될 때 그 주의 목표를 `byWeek`에 고정한다.
- 이번 주의 목표는 설정을 바꾸면 즉시 갱신하고, 지난 주는 바꾸지 않는다.
- 기존 초안(타이머·메모 버전) 데이터는 `memo` 무시, `tagId: null`로 이전한다.

## 트레이드오프 메모
- **누적 3시간**은 지키기 쉬운 대신, 짧게 쪼개진 시간도 인정되어 "몰입"의 의미는 약하다.
- **타이머 제거**로 화면은 단순해지지만, 기록 시간은 어림값이다.
- **태그**는 통계를 가능하게 하지만, 입력이 한 단계 늘고 태그 관리 화면이 생긴다. 태그를 선택 사항으로 해서 부담을 줄였다.
- **알림 없음**: 앱을 열지 않는 주에는 아무 신호가 없다. 서버 없는 원칙을 지키기 위한 선택.
- **서버 없음**: 폰을 바꾸거나 브라우저 데이터가 지워지면 기록이 사라진다. 수동 백업이 유일한 안전장치다.
- **목표 변경 가능**: 이번 주 목표는 주 중간에도 바뀌므로, 목표를 낮춰 달성하는 것을 막지 않는다. 정직함은 사용자에게 맡긴다.

## 빌드 순서 (핵심 가치 우선)
1. **기록 핵심 루프**: 빠른 입력 버튼 + 진행률 + 페이스 표시 + 이번 주 목록(수정·삭제, 지난 주 잠금). 타이머 제거, 기존 데이터 이전.
2. **휴대폰에 올리기**: PWA(manifest, 아이콘, 서비스 워커로 오프라인) + GitHub Pages 배포. 이 시점부터 실제로 쓰기 시작.
3. **태그**: 기본 태그, 입력 흐름에 태그 선택, 설정의 태그 편집.
4. **설정과 판정**: 목표 변경, 주별 목표 고정, 백업 내보내기·가져오기.
5. **돌아보기**: 지난 주들·연속 달성, 태그 비율.

## 추후 보완 계획
| 항목 | 지금 하지 않는 이유 | 다시 검토할 조건 |
|---|---|---|
| 푸시 알림 | 서버가 필요해 "서버 없음" 원칙과 충돌 | 앱 안 페이스 표시만으로 미달성 주가 반복될 때 |
| 기기 간 동기화 | 로그인·서버 필요 | PC에서도 기록하고 싶어지거나 폰 교체 시 백업이 번거로울 때 |
| 가족·친구 공유 | 사용자를 "나 혼자"로 정함 | 함께 지키고 싶은 사람이 생길 때 (동기화가 선행 조건) |
| 타이머 | 빠른 입력 중심으로 단순화 | 어림 기록이 부정확하다고 느낄 때 |
| 월별·연별 차트 | 데이터가 쌓이기 전엔 볼 게 없음 | 기록이 3개월 이상 쌓였을 때 |
